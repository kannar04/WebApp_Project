Shared execution contract

Caller identity. Only the trusted backend calls these procedures. It validates the session and supplies the authenticated p_actor_id; accepting a user-supplied actor ID would permit impersonation. Each procedure rechecks active account status, role and ownership. Authentication procedures use narrowly scoped backend access; workers use a separate privileged connection. Grant routine execution deliberately, especially for administrative and worker operations.

Transactions. Each multi-table write procedure owns one transaction, commits on success and rolls back on any SQL exception. Call it without an already-open transaction: nested transactions are not assumed. Single-row writes are atomic. Read procedures return result sets; page numbers and limits are bounded. Result sets exclude passwords, token hashes, private notes and restricted contact details unless explicitly needed by a trusted authentication flow.

Lock order. Booking creation, confirmation, cancellation, completion and calendar changes lock the listing row before booking/calendar rows. Use current locking reads for overlap and availability checks. Requests do not reserve inventory. Retry the entire call after a deadlock; confirmation locks prevent competing approvals on the same listing. Recheck the involved users with locking reads when account status affects a write.

Validation. Validate enumerated values, flags, positive capacity, nonnegative amounts/counts, coordinate pairs and date intervals inside the write procedures even if the server does not enforce CHECK constraints. Reject unknown JSON fields and invalid types. A failed ownership, lookup, transition or validation check raises a descriptive SQL error, conventionally SIGNAL SQLSTATE '45000'.

Secrets and time. The backend computes Argon2id/bcrypt password hashes and SHA-256 token hashes and generates high-entropy secrets. Procedures never receive raw passwords or raw tokens. Connections use UTC; listing-local date/cutoff calculations need verified IANA time-zone support. A missing/unknown time zone must fail validation, never silently yield a NULL calculation.

History and delivery. Mutations append events and redacted audit entries in the same transaction. History procedures expose reads; no standalone procedure allows arbitrary history edits. Email is sent by the backend worker after commit; SQL only queues and records delivery. Completed-booking totals are booked revenue, grouped by currency, not proof of collected payments.
